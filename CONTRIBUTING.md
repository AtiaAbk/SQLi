# Contributing

Thank you for considering a contribution! This project is defensive-security-focused and educational — please keep contributions aligned with that mission.

## What We Welcome
- Corrections and clarity improvements to existing content
- Additional secure-coding examples (new languages/frameworks)
- New links to legitimate, authorized learning resources or labs
- Improved diagrams, checklists, or cheat sheets
- Translations

## What We Don't Accept
- Working exploit code targeting real/unauthorized systems
- Content that assumes or encourages unauthorized access
- Attack tutorials without a paired "how to detect/prevent this" section
- Payload dumps without educational/defensive framing

## How to Contribute
1. Fork the repository
2. Create a feature branch: `git checkout -b add-golang-orm-example`
3. Make your changes, keeping Markdown formatting consistent with existing files
4. If adding a resource link, verify it's current and legitimate
5. Open a Pull Request with a clear description of what you changed and why

## Style Guidelines
- Use clear headers and tables where possible
- Keep code examples runnable/realistic, not pseudocode
- Always pair a "vulnerable pattern" example with its secure fix
- Cite sources for claims where relevant (OWASP, NIST, MITRE, official docs)

## Review Process
All PRs are reviewed for both technical accuracy and alignment with the [Ethics & Scope Statement](README.md#️-ethics--scope-statement) in the README. PRs that don't align with the defensive/educational scope will be asked for revision or declined.

Thank you for helping make this a better learning resource!
